# Contributing

## Pull requests

Keep each pull request focused on one coherent change and target `main`. Write the title and description in English.

Open a draft pull request as soon as the work branch is created, rather than waiting for implementation to finish. This is
strongly encouraged, especially for agents: it makes the work visible early and gives reviewers a place to follow progress.
Update the description and checklist as the work evolves, then mark the pull request ready for review when the change and its
validation are complete.

Use this format for the pull request description:

```markdown
## Summary

Describe what the pull request accomplishes and why.

## Changes (optional)

- List the notable changes when separate bullets make the scope clearer.

## Checklist

- [ ] Implementation is complete.
- [ ] Relevant tests and builds have been run.
- [ ] Related documentation has been updated.

## Notes (optional)

Add context, validation limitations, follow-up work, or other reviewer notes when useful.
```

`Summary` is required. Include `Changes` when it helps explain the scope; omit it when the summary is enough. Keep checklist
items relevant to the pull request, and check them off as each task is completed. Add `Notes` when there is useful context for
reviewers; otherwise, omit it.
